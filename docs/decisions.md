## Purpose
このファイルには、現時点の設計判断を記録する。
不変ルールではなく、将来変更されうる方針をここで管理する。

## Current Decisions

### ホームと予定の統合
- 初期画面はホーム。重要メール、期限超過を含む直近の締切、今後の予定を集約する。
- 説明会・逆求人・CA面談の個別管理は利用実態を踏まえ、1つの予定管理へ統合する。旧データはSQLでコピーし、旧テーブルは保持する。
- Gmailは独立した読み取り専用OAuth連携を追加する。文字列ルールで理由を示し、メールの送信や既読化は行わない。
- 名称・全体デザインは比較案を提示してから確定する。詳細・移行手順は `docs/refresh-plan.md` を参照する。

### 2026-10-15: 選考区分・ラベルの整理
- 応募区分に冬インターンと早期選考を追加。既存値は維持する。
- ステータスは進行状況、応募区分は募集の種類、選考内容は必要な選考方法として分離する。
- 選考内容にエントリーシート・課題提出を追加。GDの保存値は維持して表示をグループディスカッションへ変更する。
- 締切はES以外にも使うため「ES締切」から「締切」へ変更する。
- DBへの適用には `0014_expand_application_types.sql` が必要。

### 1. 日時の扱い
- 面談日時や締切日は、ユーザーが入力したローカル時刻として扱う
- UI 上では、入力した日時と同じ見え方になることを優先する
- 実装時は「保存時」「取得時」「表示時」の各段階でタイムゾーンずれが起きないようにする

### 2. 締切日の自動リマインド
- まずは画面表示のみを行う
- 対象は、締切日の表示・近接警告・期限切れ表示
- 通知、メール送信、バックグラウンドジョブはこの時点では扱わない

### 3. 面談メモテンプレ
- 面談後の感想・魅力点・懸念点・次回聞きたいことは、まず memo に含める
- 直ちに構造化カラムへ分離しない
- テンプレ入力は UI で補助し、保存先は既存 memo を使う

### 4. 逆求人イベント記録
- 既存 application とは別概念として扱う
- 通常応募とは異なる接点情報として整理する
- application に無理に押し込まず、必要なら専用エンティティを設ける前提で考える

### 5. メール文面生成
- メール文面は自動生成だけでなく保存も行う
- 生成結果を一時表示で捨てず、履歴として扱える設計を前提にする
- 送信機能を直ちに含めるかどうかは別判断とする

## Decision Update Rule
