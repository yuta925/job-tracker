# ホーム・選考管理の見直し

## 実装したこと

- ログイン後の初期画面をホームに変更。選考ボードは「選考管理」から開く。
- ホームの「企業を追加」ボタンを削除。企業の新規登録は選考管理にまとめ、ホームは情報確認を中心にする。
- ホームには進行中の選考数、7日先までの締切（期限超過を含む）、7日先までの予定、重要メールを表示する。
- 内定・お見送りの応募は直近の締切や面接予定から除外。今日の予定は開始済みでも当日中は表示する。
- 応募区分に冬インターン・早期選考を追加。フォーム、カード、詳細、絞り込みで共通の定義を使う。
- 選考内容にエントリーシート・課題提出を追加。GDは表示上「グループディスカッション」とする。
- 説明会・逆求人・CA面談の個別フォームを、予定名・日付・時刻・URL・メモの共通フォームに統合。
- 応募データをホームとボードで共有し、追加・変更を即時反映する。
- 就活サイト・自己分析は、開いたときだけ取得する。

## 機能の整理

利用率の計測は実装されていない。実際の利用頻度はコードから断定せず、ユーザーの回答と参照関係に基づいて整理した。

| 機能 | 判断 | 根拠 |
| --- | --- | --- |
| 説明会・逆求人・CA面談の個別管理 | 共通の予定に統合 | ユーザーがほぼ使っていないと回答。入力項目とCRUDが重複していた。 |
| 古い説明会カレンダー・一覧・カード | 削除 | 現在のダッシュボードから使われておらず、統合カレンダーと重複。 |
| document_itemsの型・クエリ | 削除 | UIから参照されていない未使用コード。DBテーブルは保持。 |
| 就活サイト・自己分析・履歴書プロフィール | 維持 | 使用しないという根拠がなく、既存データの利用先でもある。 |
| Googleカレンダー連携 | 維持 | 統合した予定と面接から登録できるように更新。 |
| メール生成・分析グラフ・自動通知 | 追加しない | 今回のホームと選考の整理に必要な範囲を優先。 |

## Gmailの対象と制約

- 読み取り専用スコープ `gmail.readonly` を使用する。
- 対象は受信トレイの直近14日・最新50通。プロモーション・ソーシャルを除く。
- 登録企業名と件名・送信者・抜粋を照合する。未登録企業でも、個別の選考結果や面接案内を示す明確な件名は対象にする。
- 「選考結果」「締切・提出」「面接・日程調整」「返信・対応依頼」の理由を表示する。
- 未読を優先し、その後に種類・受信日時で並べる。ホームには先頭3件を表示する。
- 判定は文字列ルールによるもの。すべての重要メールを拾う保証はなく、Gmail本体の確認も必要。
- 抜粋はGmailが返すテキストを表示する。本文のHTML表示、外部AIへの送信、メール本文のDB保存は行わない。
- 更新ボタンで再取得。既読化・送信・削除・自動返信は行わない。
- 更新トークンはAES-256-GCMで暗号化し、ユーザー単位のRLSを適用したテーブルへ保存する。API応答へトークンを含めない。
- OAuthのstateは現在のログインユーザーに結び付ける。連携解除は保存トークンの削除を行う。

公式仕様: [messages.list](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list)、[messages.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/get)、[スコープ](https://developers.google.com/workspace/gmail/api/auth/scopes)。

## 実環境で利用するための設定

1. 既存DBには `0014` → `0015` → `0016` → `0017` の順で移行SQLを適用する。新規DBは `0001` からすべて適用する。
2. `0015` は旧3テーブルのデータを `schedule_events` にコピーする。元テーブルは保持するが、コピー後の旧テーブルの更新は新画面に同期しない。デプロイ時は旧バージョンからの入力を止めて切り替える。
3. Google CloudでGmail APIを有効化し、OAuthの許可済みリダイレクトURIへ `/api/gmail/callback` の完全URLを追加する。
4. `web/.env.example` を参考に、OAuthクライアント、`GMAIL_REDIRECT_URI`、暗号化キーを設定する。暗号化キーは `openssl rand -base64 32` で生成し、連携後は変更しない。
5. Google OAuthがテストモードなら利用アカウントをテストユーザーへ追加する。一般公開する場合の審査要件は上記スコープ資料で確認する。
6. アプリのホームからGmailを連携する。Googleカレンダーの既存連携とは別に許可する。

DB接続情報とOAuth認証情報はこの作業環境にないため、本番へのSQL適用・Google側の設定・実アカウントでの受信確認は未実施。
